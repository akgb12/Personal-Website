# Copy Guide

## Voice

Natural, technically literate, understated.

The user wants copy that sounds like something he would actually say, not marketing copy written by a startup landing-page generator.

## Do

- use direct sentences
- state concrete facts
- keep paragraphs short
- prefer “I’m a Computer Science and Statistics student...” over grand statements
- let projects/research demonstrate sophistication
- use technical terms when they are accurate

## Do not

Do not write:
- “I build products that think, scale, and breathe.”
- “Crafting intelligent experiences at the intersection of...”
- “Building the future, one line of code at a time.”
- “Passionate developer.”
- “Turning ideas into reality.”
- “Where code meets creativity.”
- “Pushing the boundaries of innovation.”

Avoid empty phrases like:
- cutting-edge
- game-changing
- revolutionary
- world-class
- visionary
unless a factual source genuinely requires them.

## About

Recommended starting copy:

> I'm a Computer Science and Statistics student at Texas A&M interested in software engineering, AI systems, and machine learning. My experience spans full-stack development, cloud systems, research, and teaching.

## Project copy

Use 1–2 concise sentences per project.
Do not paste résumé bullets.

Good:
“Sapphire is a Google-sponsored platform for translating legacy code into user-selected stacks, using a LangGraph-orchestrated Gemini pipeline for translation, validation, and test generation.”

Bad:
“Built a web platform... • Led a team... • Designed UI... • Orchestrated...”

## Experience copy

Role metadata is primary.
If a description is present, one compact sentence maximum.

## Research copy

Explain the problem and technical direction.
Do not overstate incomplete/unpublished work.

## Publication copy

Use the exact formal title and citation.
The visual title can be split across lines, but wording must not change.
